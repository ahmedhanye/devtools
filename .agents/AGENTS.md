# Agent guidelines

## Context

- **Documentation.** Always read the relevant guide before acting: `TESTING.md` for tests, `CODING_STANDARDS.md` for code and APIs, `REVIEW.md` for verification and diffs, `ARCHITECTURE.md` for system design and the ADR index (`docs/adr/`), `CONTRIBUTING.md` for git, issue, and PR workflows, and `GLOSSARY.md` for domain terms.

## Execution boundaries

- **Bounded, non-interactive execution.** Pass non-interactive flags such as `--yes`, `-y`, `--no-interactive`, `--short`, or `--json` to CLI tools, suppress pagers with `PAGER=cat` or `--no-pager`, and avoid commands that wait on TTY input. Wrap inline scripts, local server probes, and network CLI calls in explicit shell timeouts such as `timeout 20s` or `curl --max-time` so deadlocked or stalled processes exit instead of hanging. Use `fetch` or asynchronous child spawns instead of synchronous child processes against an in-process server on the same event loop, and pass `--max-columns` or exclude `*.map` files when searching dependency directories. When command output is truncated to a log file, read the saved log instead of re-running the command.
- **Path portability.** Use repository-relative paths for all tracked codebase files, documentation, git commit messages, and symbol references. Never commit absolute machine paths or `file://` URIs in tracked repository files or shell commands. Restrict absolute filesystem paths and clickable `file://` links strictly to agent chat responses, ephemeral local session artifacts, transcripts, and temporary analysis files under `.scratch/` for IDE navigability.
- **Temporary file hygiene.** Write to `.scratch/` only when explicitly designated. Keep ad-hoc scripts and temporary files inside the agent session scratch directory or run inline commands without leaving untracked files.
- **Secret handling.** Never write sensitive data or credentials into the repository. Store runtime secrets in gitignored `.env` files. Append `// trufflehog:ignore` in `//`-comment files or `# trufflehog:ignore` in `#`-comment files, and only when a test fixture is completely fake.
- **Git and GitHub write boundaries.** Keep `git` and `gh` read-only during ordinary code or doc requests: editing files does not authorize committing, pushing, merging, creating or updating PRs, or mutating stacks. Require an explicit user request, an invoked git, PR, or ticket workflow, or confirmation before those writes, and always ask before destructive, force, or protection-altering actions (such as `git reset --hard`, `git push --force`, branch deletion, or ruleset edits).
- **No remote polling.** After pushing commits, opening or updating PRs, or posting review replies, report the result and end your turn. Never schedule timers, background tasks, `--watch` flags, or polling loops to wait on remote CI checks, automated reviewers, or new PR comments unless the user explicitly asks to watch a run.
- **Package manager and runner.** Use `bun` and `bunx` for package installations and package scripts. Translate `npm`, `npx`, or `pnpm` references to their `bun` equivalents or workspace scripts.
